## 三、F-04 数据 API：会话隔离 / 结构 / 空态（通过）

### 3.1 `GET /api/compliance`

- 匿名 401；空库返回五个分组（`policyUpdates/taxReminders/complianceChecks/riskItems/suggestions`）**全部为空数组**，键名完整。
- 种子后每用户 24 条，按 `user_id` 隔离；alice 与 bob 的条目 id 无交集，数据库行数各 24。
- 条目结构：`id + payload 展开字段 + createdAt`；**损坏 payload 不抛 500**，行仍以 `id/createdAt` 返回（容错）。

### 3.2 `GET /api/ad-campaigns` 与 `/api/ad-campaigns/[id]`

- 匿名 401；空库返回 `{campaigns:[], suggestions:[]}`（空数组，非 null）。
- 种子后每用户 3 条 campaign + 3 条 suggestion；两用户 id 不重叠。
- campaign 结构：`id/externalId/name/platform/status/budget/spent/roas/clicks/conversions/ctr/audience/creatives/createdAt`；`audience` 为对象、`creatives` 为数组；suggestion 含 `campaignExternalId/title/status`。
- 详情支持数字 id 与 `externalId` 两种标识；跨用户与未知 id **统一 404** `CAMPAIGN_NOT_FOUND`（不泄露存在性）。

### 3.3 `GET /api/profile`

- 匿名 401；返回 `{user, preferences, sessions}`；`user` 不含 password；未初始化偏好时 `preferences=null`。
- `sessions` 只含当前用户，标记当前设备；**序列化结果不含 token_hash/64 位哈希**。
- 多会话：同用户 2 个会话时任意一个视图均显示 2 条，且恰有 1 条 `current:true`；不同用户会话互不出现。

### 3.4 `GET /api/orders/[id]`

- 匿名 401；本人订单可按数字 id 与 `order_number` 查询，返回 `order{shopId,shopName,shopDomain,orderNumber,customerName,totalAmount,status,shippingRegion,shippingWeight,logisticsChannel,createdAt}` + `items:[]` + `tracking:[]`。
- 跨用户 404 `ORDER_NOT_FOUND`、未知 404、非法 id 404；订单列表接口（`/api/data?type=orders`）按用户过滤（每用户 3 单）。

> 四类数据（合规 / 广告活动 / 订单 / 会话资料）的隔离均由上述独立用例 + 既有 `data-filters` 用例双重覆盖。

## 五、selection 页随机评分的评估（F-04 残留判定）

**现象**：[app/dashboard/selection/page.tsx](../../sumaitong/app/dashboard/selection/page.tsx#L27-L45) 从 `/api/data?type=products` 取真实商品后，展示层构造：
- `score: p.score || Math.floor(Math.random() * 30 + 70)` —— 后端商品无 `score` 字段 → **每次刷新评分随机变化**；
- `demand: p.demand || '中等'`、`competition: p.competition || '低'`、`profit: p.profitMargin ? … : '--'` —— 静态兜底；
- 请求携带 `agentType=selection`，但 `/api/data` 的 products 分支**不消费 agentType**，返回当前用户全部商品。

**判定**：属于 F-04「硬编码/伪数据」同类残留，但**不在 F-04 原始五个页面清单内**（P0 文档列的是任务日志/合规/投流/数据中心/任务详情），且不阻断主链路：
- 影响：推荐评分/需求/竞争度为展示层合成，与真实算法结果无关，演示时可能被质疑数据真实性；
- 级别：非阻断（P2 级展示问题），不影响接口隔离与业务闭环。

**建议**：由后端返回评分/需求/竞争度字段（selection Agent 已有 `scores` 计算，可落库或实时计算），或在页面隐藏“评分/需求/竞争度”列或标注“估算值”；同时修正 `/api/data` products 的 `agentType` 参数语义（当前静默忽略）。

## 六、其他发现与残余风险

| 编号 | 项 | 说明/建议 |
| --- | --- | --- |
| R1 | selection 展示层随机评分（见第五节） | 非阻断；建议后端给分或隐藏该列 |
| R2 | 合规/投流数据来源仅为演示种子 | `compliance_items/ad_campaigns/ad_suggestions` 无真实外部来源（无 Shopify 广告同步、无合规数据接入）；`SEED_DEMO_DATA` 未开启时两页为空态（符合预期但演示需显式开启） |
| R3 | 订单明细/物流轨迹无数据表 | `items/tracking` 恒为 `[]`（代码注释明确不伪造）；后续需建表或接物流接口 |
| R4 | 广告数据只读 | 无 campaign 创建/编辑接口，页面“优化建议”处理仅为前端本地状态 |
| R5 | 个人中心会话列表只读 | 显示 device/ip 恒为“未知”（未采集 UA/IP），无“退出其他设备”操作 |
| R6 | data-center 流量来源/转化率未接入 | 固定空数组/`null`，图表趋势 `flat` 为占位 |
| R7 | 页面 401 降级为空态 | 直接访问页面且会话过期时先显示空数据再跳登录，短暂空态可能被误认为“无数据”（体验项，非安全问题） |
| R8 | 种子依赖 | 演示数据仅在 `SEED_DEMO_DATA=true` 时写入；生产/空库需明确数据初始化流程 |
| R9 | 列表接口无分页 | compliance/ad-campaigns 一次性返回全量（按用户），数据量大时需分页 |
| R10 | 既有跨用户测试覆盖 | 本次新增独立用例与既有 `data-filters`/`admin-shop-detail` 等互补，均通过 |
